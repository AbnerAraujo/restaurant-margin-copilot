What's left

One shipped since the freeze — one deliberately gated

Shipped — paraphrase-aware cache (spec 004)
  • On a miss: one Haiku 4.5 classification against a bounded list of cached questions — no embeddings, no second vendor
  • Uncertain match → treated as new. Refuse-to-reuse, Principle II applied to caching
  • The classification call is itself instrumented with real cost
  • Live-verified: a genuine paraphrase served from cache at real, disclosed classification cost; a meaningfully different question correctly missed
Gated on human review — multi-tenant (spec 005 + RFC)
  • A tenant-isolation bug is a data-breach class of defect — Restaurant A seeing Restaurant B's margins
  • Fails closed: tenant_id is a required parameter in every sqlc query signature — forgetting the filter is a compile error, not a leak
  • Identity flows from authenticated context, never client input; cache keys become per-tenant
  • An adversarial isolation test suite is the release gate

Where it went wrong — and how it was caught

From the real mistakes log, kept as it happened

The sentinel-date collision that silently deleted $152.50

A test used a real in-range date as its fixture key; its cleanup DELETE destroyed the pipeline's real row. The agent reported 14 days persisted. Caught by an independent psql query — 13 rows, short by exactly 152.50.

The model was quietly doing arithmetic — and passing tests for it

No tool returned a combined delivery total; the model was summing the map itself — a Principle I violation that passing scores rewarded by accident. The honest fix was a deterministic Go field, not more prompt engineering.

My own git add -A, during an overnight session

A "cleanup" commit swept a background agent's half-finished edits onto main; briefly, the tree didn't build. Caught by running go build on principle. The misleading commit message stays in history — disclosed, not rewritten.

Roadmap · not yet built

Closing every manual-file gap left in the pipeline

The supplier cost sheet is the one input the owner constructs themselves, on an irregular cadence. Sales data has the same problem one step removed: someone still exports a CSV from iFood's and Just Eat Takeaway's merchant portals rather than the product pulling it directly.

Near-term · cost side

Snap the Invoice

A photo or forwarded PDF, extracted by Claude vision into the exact typed CSV shape spec 007 already validates — the deterministic pipeline never changes, only the front door does. Confirmation stays mandatory; low-confidence fields are flagged, never guessed.

Real risk: thermal-paper and handwritten invoices from small suppliers will sometimes make confirming slower than re-keying.

Medium-term · both sides

Prosus Rails First

Structured feeds direct from suppliers AND platforms — starting inside Prosus's own merchant network (iFood leads; it's an internal conversation there), not the fragmented open market. Needs Phase 1's field data first, and real BD/partner-approval cycles.

Real risk: a platform's real-time order feed and its end-of-period payout statement routinely disagree for days — a day without settled data is flagged provisional, never estimated.

Stretch · cost side

Price Watch

The existing discrepancy-flag mechanism, extended: Go computes trailing per-supplier unit-cost baselines and flags a jump before it silently erodes margin. Sonnet only narrates the flag — worthless without Phases 1–2's data density.

Real risk: seasonal produce volatility creates false positives that teach the owner to ignore alerts.

One move, two sides: every number the reconciliation engine consumes stops arriving as a manually produced file — costs via invoice capture and supplier feeds, sales via platform APIs — until the owner's only job is reading the answer. Why Prosus, not a generic SaaS vendor: it sits on both sides of the invoice AND owns iFood — standardizing at the rail level, not integration-by-integration.
